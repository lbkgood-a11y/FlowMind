# TrioBase 注释规范

## 1. 目标

注释用于保存代码本身无法完整表达的业务意图、边界、不变量和取舍。注释不是代码的中文翻译，也不能替代清晰命名、合理拆分、测试、OpenSpec、ADR 或 API 文档。

所有新增和修改都必须评估相关注释：行为、边界或契约发生变化时，同一变更必须新增、更新或删除对应注释；纯拼写、格式或显而易见的局部调整无需强行增加注释。

## 2. 规则级别

| 级别 | 含义 | 增量门禁 |
|---|---|---|
| `BLOCKER` | 缺失会导致调用错误、安全风险或业务语义无法确认 | 阻断 |
| `ADVISORY` | 有助于维护但不影响当前安全性或契约 | 报告，触达时整改 |
| `PROHIBITED` | 注释内容本身构成风险或长期债务 | 阻断 |

### 2.1 稳定规则 ID

| ID | 级别 | 规则 | 修复方式 |
|---|---|---|---|
| `CG-B001` | BLOCKER | 新增公共契约缺少调用方语义 | 补充职责、边界、返回、异常和兼容说明 |
| `CG-B002` | BLOCKER | 高风险逻辑缺少安全不变量 | 在决策点解释权限、幂等、事务、并发或补偿边界 |
| `CG-B003` | BLOCKER | 注释与实现或测试矛盾 | 更新或删除失效注释，并同步测试 |
| `CG-B004` | BLOCKER | 关键行为承诺没有验证证据 | 增加单测、契约测试、集成测试或架构测试 |
| `CG-B005` | BLOCKER | 豁免缺少必要元数据 | 补齐规则、原因、负责人和到期/移除条件 |
| `CG-A001` | ADVISORY | 存量公共契约缺少说明 | 在模块补齐波次或触达时整改 |
| `CG-A002` | ADVISORY | 注释位置或格式不符合语言惯例 | 移到拥有该不变量的最小作用域并使用标准格式 |
| `CG-A003` | ADVISORY | 隐式单位、排序或生命周期未说明 | 补充单位、时区、精度、顺序或生命周期 |
| `CG-P001` | PROHIBITED | 注释含真实敏感信息 | 删除并按安全事件流程轮换已暴露凭证 |
| `CG-P002` | PROHIBITED | 注释掉的代码或个人变更历史 | 删除；历史交由 Git 保存 |
| `CG-P003` | PROHIBITED | TODO/FIXME 无负责人、任务和移除条件 | 补齐临时注释元数据或立即解决 |
| `CG-P004` | PROHIBITED | 批量复述代码的模板注释 | 删除低价值注释，必要时改为解释原因和不变量 |

## 3. 必须注释的场景

### 3.1 公共契约

跨文件、模块、服务或语言边界使用的类型、接口、DTO、事件、工具和扩展点，在类型系统不能完整表达时必须说明：

- 职责与事实 Owner；
- 重要参数、返回值、异常和空值语义；
- 生命周期、兼容策略和调用方假设；
- 时间、金额、容量、分页等单位和边界。

### 3.2 高风险实现

以下逻辑必须在约束发生的位置解释不能破坏的不变量：

- 认证、授权、租户隔离、组织数据范围和默认拒绝；
- 敏感信息过滤、审计、TraceId 和安全降级；
- 事务边界、幂等键、锁顺序、并发和缓存一致性；
- Temporal 确定性、Activity I/O、重试、补偿和副作用；
- 跨服务 Owner 边界、事件顺序、重复投递和兼容；
- AI Action、工具注册、人工确认和权限过滤；
- 复杂状态机、非常规算法、性能优化和兼容分支。

### 3.3 数据和配置语义

- 数据库迁移：目的、数据假设、不可逆风险、大表影响和回滚要求；
- 配置项：默认值、合法范围、启停效果、生产建议和是否需要重启；
- Feature Flag：关闭行为、回滚作用和移除条件；
- 缓存：Key 构成、TTL 原因、失效策略和一致性边界；
- 时间：时区、时间来源以及业务时间或处理时间；
- 金额：币种、最小单位、精度和舍入规则；
- 分页/集合：稳定排序键、去重规则和并发写入影响；
- 事件：事实成立时点、Owner、顺序、重复消费、幂等和补偿。

## 4. 不应添加注释的场景

以下内容通常无需注释：

- getter/setter、显而易见的赋值和简单分支；
- 已由准确名称和类型完整表达的局部变量；
- 逐行解释“正在调用方法”“判断为空”“返回结果”；
- Git 已记录的作者、日期和修改历史；
- 被注释掉的旧代码。

不合格示例：

```java
// 获取数据范围
DataScope scope = dataScopeService.resolve(userId);

// 如果为空则返回空列表
if (organizationIds.isEmpty()) {
    return List.of();
}
```

合格示例：

```java
/*
 * 无法解析组织范围时必须默认拒绝。禁止回退为租户全量数据，
 * 否则配置错误会被放大为越权读取。
 */
if (organizationIds.isEmpty()) {
    return List.of();
}
```

## 5. 语言规范

### 5.1 Java

- 公共类型和跨模块接口使用 Javadoc；只有调用方需要的信息才使用 `@param`、`@return`、`@throws`。
- Spring Controller 说明接口职责和安全前置条件；Service 说明业务不变量；DTO 说明跨服务契约。
- Workflow 注释确定性和状态推进；Activity 注释 I/O、副作用、重试、幂等和补偿。

```java
/**
 * 返回当前用户可访问的组织集合。
 *
 * <p>结果已经过租户和数据范围过滤，调用方不得与未授权组织数据合并。</p>
 */
List<Organization> listAccessibleOrganizations(String tenantId, String userId);
```

### 5.2 Python

- 公共模块、类和函数使用符合 PEP 257 的 docstring。
- 路由、Agent 工具和模型适配器说明权限、数据清洗、错误和跨语言序列化契约。

```python
def register_permissions(application_id: str, release_version: str) -> Result:
    """注册应用版本的权限资源。

    重复调用以应用 ID 和发布版本作为幂等身份；注册中心不可用时返回
    可重试错误，禁止将应用标记为已成功发布。
    """
```

### 5.3 TypeScript/Vue

- 公共 API 客户端、store、composable 和 registry 使用 TSDoc/JSDoc。
- Vue 中复杂 watch、副作用、SSE 重连和 LUI→GUI Action 流需解释状态边界。

```ts
/**
 * 加载后端已过滤的组织树。
 * 缺失节点可能代表无权查看，前端不得通过其他接口补齐。
 */
async function loadAccessibleOrganizationTree(): Promise<void> {
  // 请求失败时清空旧数据，避免权限回收后继续展示缓存结果。
  organizationTree.value = await organizationApi.listAccessibleTree()
}
```

### 5.4 SQL

迁移文件头必须说明目的、不变量和回滚影响；危险 DML、批量回填和唯一约束需紧邻说明。

```sql
-- 目的：为应用权限注册增加业务级幂等约束。
-- 不变量：同一租户、应用和发布版本只能注册一次。
-- 回滚：删除索引前必须先确认没有依赖该约束的并发发布任务。
CREATE UNIQUE INDEX uk_app_permission_release
    ON application_permission_registry (tenant_id, application_id, release_version);
```

### 5.5 YAML 与脚本

只解释非默认配置、依赖、失败影响、安全边界和重启要求；不要为每个键重复官方名称。

```yaml
# 权限服务名在启动时绑定，修改后需要重启 service-org。
# 服务不可用时数据权限查询必须失败关闭，禁止降级为全租户可见。
data-scope:
  service-name: service-auth
```

## 6. 临时注释、引用和豁免

### 6.1 TODO/FIXME

```java
// TODO(TRIO-1234, owner=platform-team, remove-when=权限投影完成全量切换):
// 删除同步查询兼容路径。
```

无任务编号、负责人或清理条件的临时注释禁止合入。

### 6.2 决策引用

```java
// ADR-003 选择受治理的 Action 入口；这里拒绝任意 URL，
// 保证 Agent 的副作用仍经过授权、确认、幂等和审计。
```

不能只写 `See ADR-003`，代码附近必须保留足够的安全上下文。

### 6.3 扫描豁免

```text
comment-governance-disable-next-line CG-B001
reason=框架反射入口且无外部调用方; owner=platform-team; expires=2026-10-01
```

豁免必须作用于最小范围；到期或缺少元数据时 CI 失败。

## 7. 生成代码与 AI 注释

生成文件必须声明生成器、再生成方式和禁止手工修改：

```text
Generated by OpenAPI Generator.
Regenerate with: ./mvnw generate-sources
DO NOT EDIT MANUALLY.
```

AI 可以起草注释，但作者必须根据实现、契约和测试核验。禁止只根据方法名批量生成模板注释并直接提交。

## 8. 注释与测试

注释中关于权限边界、默认拒绝、校验范围、降级、幂等、补偿、顺序和兼容性的承诺，必须有可定位的自动化验证。纯职责说明和背景理由不要求单独测试。

评审时检查四个问题：

1. 为什么要这样实现？
2. 哪个约束不能被破坏？
3. 失败时系统如何处理？
4. 是否有测试证明关键承诺？

## 9. 变更评审清单

- [ ] 公共契约说明了调用方需要的边界，而非复述类型。
- [ ] 高风险决策说明了安全不变量、失败策略或取舍。
- [ ] 行为变化同步更新或删除了旧注释。
- [ ] TODO/FIXME 和豁免包含完整生命周期元数据。
- [ ] 注释不含真实凭证、个人数据或可利用的安全细节。
- [ ] 关键行为承诺存在对应测试或其他可执行证据。
- [ ] 删除实现时同步删除了失效注释、配置说明和文档引用。
