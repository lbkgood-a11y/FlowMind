# 低代码表单授权生产运行手册

## 闭环与就绪条件

低代码表单或应用发布时，业务状态与授权发布事件在同一数据库事务内提交。运行时只暴露同时满足以下条件的快照：

1. 业务状态为 `PUBLISHED`；
2. `authorization_status` 为 `SYNCED`；
3. 授权确认对应当前 `schema_hash` 或 `metadata_hash`，不存在旧快照确认冒充新快照的情况；
4. 授权中心中的语义资源为 `ACTIVE`，且调用者获得具体资源和动作的允许决策。

任一依赖不可用、资源缺失、快照未确认、决策拒绝或应用已下线时均 fail closed。

## 管理操作

在“系统管理 → 企业授权 → 低代码应用授权”中：

1. 选择角色和已发布应用；
2. 选择申请人、审批人、设计者或管理员套餐；
3. 先执行“预览差异”，核对将新增的应用与表单语义动作；
4. 执行“原子应用”。请求使用幂等键，可安全重试；同键不同请求会被拒绝；
5. 在“发布授权链路诊断”确认事件状态为 `ACKNOWLEDGED`。

套餐只新增明确的 `ALLOW`，不会删除已有授权，也不会覆盖显式 `DENY`。审批动作仍受候选人、禁止自审和单据状态守卫约束。

## 告警与处置

建议采集结构化日志 `Lowcode authorization publication acknowledged/failed`，并按以下条件告警：

- `FAILED` 事件数量大于 0：立即告警；
- `PENDING`/`RETRYING` 最老事件超过 5 分钟：告警；
- `RUNNING` 超过 2 分钟：调度器会自动回收租约，仍存在则告警；
- 运行态请求出现 `LOWCODE_AUTHORIZATION_SNAPSHOT_NOT_READY`：阻止上线并检查同步链路。

处置顺序：先恢复 `service-auth` 及内部服务令牌，再点“重试”；若授权目录与业务快照存在漂移，点“对账”生成新的不可变修复事件。不要直接修改授权目录表。

## 部署与回滚

部署顺序：先部署 `service-auth`（执行 V87、V88），再部署 `service-lowcode`（执行 V13），最后部署前端。首次上线应确认两个服务的 Flyway 均成功、内部同步接口可达，并完成一个测试应用的发布—确认—授权—运行—下线验收。

回滚应用代码时保留新增表和列；它们向后兼容且承载审计证据。不要回滚或删除已执行的 Flyway 迁移。紧急情况下可停止低代码入口流量，修复服务后通过重试/对账恢复，禁止绕过 `SYNCED` 门禁。

## 生产验收清单

- 发布后授权中心不可用：业务快照不可运行，事件进入重试；
- 服务恢复：相同事件幂等确认，快照转为 `SYNCED`；
- 申请人仅可执行申请套餐动作；审批人审批仍需通过工作流守卫；
- 无授权、显式拒绝、资源缺失、决策超时全部拒绝；
- 下线确认后资源变为 `INACTIVE`，历史授权保留但不可生效；
- 旧发布事件迟到不能覆盖更新版本或已确认的同版本下线；
- 对账事件可修复目录漂移且不会产生重复授权副作用。
