## Why

TrioBase 的 Java、Python、TypeScript/Vue、SQL 与配置代码缺少统一的注释契约，关键业务意图、权限边界、幂等与跨服务约束只能依赖个人经验理解，增加了维护和变更风险。需要把“必须解释为什么、禁止复述代码、存量逐步补齐、新增变更强制遵守”固化为仓库级规范与可持续门禁。

## What Changes

- 建立覆盖 Java、Python、TypeScript/Vue、SQL、YAML 与脚本的统一注释规范，明确必备注释场景、语言格式、质量要求、豁免范围与反例。
- 将权限/租户/数据范围、事务/幂等、Temporal 确定性、跨服务契约、AI 治理、安全降级、复杂状态机和非常规算法列为强制解释项。
- 建立全仓库存量注释盘点和分批补齐机制，优先处理公共契约与高风险业务路径，避免机械地为每行代码生成低价值注释。
- 为后续新增和修改代码增加“随变更补注释”的差异化门禁，并通过基线避免历史债务一次性阻塞所有开发。
- 将规范写入工程文档和仓库级 AI/开发约束，在代码评审、静态检查与 CI 中持续执行。
- 增加规范符合性测试、豁免登记和注释债务报告，使执行结果可审计、可逐步收敛。
- 统一注释语言、位置和生命周期，并规范 TODO/FIXME、决策来源引用、生成代码声明和 AI 生成注释的人工确认责任。
- 对数据库字段、配置项、Feature Flag、缓存、并发、时间、金额、分页、事件和性能优化建立专项说明要求。
- 要求权限、边界、降级、幂等等可验证承诺具备对应测试，避免注释与真实行为脱节。

## Capabilities

### New Capabilities

- `code-comment-governance`: 定义全语言注释质量契约、存量补齐策略、变更级门禁、豁免与审计要求。

## Impact

- 影响仓库根级开发约束、工程规范文档、Maven/前端/Python 静态检查、Harness CI 以及代码评审模板。
- 影响所有 Java 微服务、Python AI/数据服务、前端 TypeScript/Vue、数据库迁移、配置和运维脚本。
- 不改变对外 API 或业务数据模型；新增门禁将先以存量基线运行，再对新增/修改代码强制执行。
